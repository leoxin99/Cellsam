## 2. 为什么推理阶段会有“冲突像素”

在多框推理中，每个框都会单独产生一张概率图；当两个（或更多）框的前景区域在同一像素位置同时超过阈值，就会出现“冲突像素”。

- 对应实现：`src/inference/core.py:258` 的 `resolve_conflicts()`
- 输入：`pred_stack[N,H,W]`（N 个实例的预测）
- 冲突定义：`overlap_count >= 2`（`src/inference/core.py:281`-`src/inference/core.py:283`）
- 冲突归属策略：
  - `argmax_prob`：归给概率最高实例（默认）
  - `first_write`：先写入者保留
  - `last_write`：后写入者覆盖

这也是为什么即使是推理阶段，也必须显式做冲突裁决。

## 6. 全项目已实现内容总览（设计 / 功能 / 效果 / 优缺点）

### 6.1 Foundation 与总体架构

- 设计：以 `CellSAM` 作为基础分割模型，不改 `cellSAM_source` 源码主逻辑；在本项目侧实现训练、检测、推理、评估编排。
- 功能：实现“可替换检测器 + 统一推理核心 + 可插拔损失函数”的模块化流程。
- 效果：保留 Foundation 模型泛化能力，同时能针对心肌细胞粘连问题持续迭代。
- 优点：低侵入、版本可控、便于对比实验。
- 缺点：端到端效果受外部检测质量影响明显（Oracle 与 E2E 有 gap）。

### 6.2 检测与框来源（GT / DAPI）

- 设计：训练阶段优先使用 GT 框学习“给定框内的纯分割能力”；部署阶段使用 DAPI 检测框进行 E2E 评估。
- 功能：拆分“分割能力上限”与“检测误差影响”，避免问题混叠。
- 效果：已明确当前瓶颈主要在 E2E 链路（检测 + 冲突传播），不是纯分割上限。
- 优点：诊断清晰，可定向优化 RQ/SQ。
- 缺点：训练和部署输入分布不完全一致，域差会带来性能回落。

### 6.3 统一推理核心（Phase 0）

- 设计：将推理聚合到 `src/inference/core.py`（`InferenceConfig` + `segment_with_boxes` + 冲突裁决）。
- 功能：统一验证、Oracle 评估、E2E 评估的推理口径，避免脚本各自硬编码。
- 效果：同一 checkpoint 的跨脚本结果可比性大幅提升，减少“指标口径漂移”。
- 优点：可复现性强，后续改策略只改一处。
- 缺点：冲突裁决当前仍以规则策略为主（`argmax_prob` / `first_write` / `last_write`），非全局最优化。

### 6.4 训练优化 Phase 1（已锁定）

- 设计：以不改主干为原则，做 loss 重平衡并启用 PQ early stop。
- 功能：提升实例级质量（BM/PQ/AJI），并通过标准化评估脚本在 test 集锁定结果。
- 效果（test 锁定）：Oracle BM-1to1=0.6954，PQ=0.4641，AJI=0.5195；E2E BM-1to1=0.5446，PQ=0.1719，AJI=0.3181。
- 优点：对基线有明确增益，结论稳定。
- 缺点：E2E 端仍有明显下降，说明“相邻侵占 + 检测误差”尚未根治。

### 6.5 训练优化 Phase 2 Step 3（已实现，待 Step 4 训练验证）

- 设计：新增 `L_neighbor` 与 `L_overlap`，显式惩罚相邻细胞像素互侵和多实例重叠占用。
- 功能：从损失层面对“粘连细胞互相侵占”给出直接约束。
- 效果：代码实现、梯度门禁、回归测试均已通过，当前进入 P2-A 训练阶段验证收益。
- 优点：目标对齐业务痛点；与现有框架兼容，改动可控。
- 缺点：当前 overlap 仍是单趟近似，存在顺序依赖；是否带来稳定指标提升需以训练结果确认。

### 6.6 评估与质量保障体系

- 设计：Oracle 与 E2E 双轨评估 + 回归测试 + 训练前配置检查。
- 功能：
  - `tools/comprehensive_eval.py`：Oracle(test) 最终评估
  - `tools/evaluate_e2e.py`：E2E(test) 部署评估
  - `tools/smoke_test_e2e.py`：开发期快速验证（默认 30 样本）
  - `tools/test_unified_regression.py`：统一口径回归
  - `tools/verify_training_config.py`：训练前配置与 SLURM 环境检查
- 效果：显著降低“环境问题/口径不一致”导致的无效训练和误判。
- 优点：工程鲁棒性提升，支持 Alice 与本地协同。
- 缺点：评估链路变长，执行成本上升，需要严格流程纪律。
